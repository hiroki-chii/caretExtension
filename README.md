# Caret Mode（Windows向け試作）

入力待機中に、キャレット上部へ「あ」「A」「全A」「カ」「ｶ」を表示するRust製の常駐アプリです。文字入力・削除・貼り付けで非表示になり、操作停止から700ms後に再表示します。IME変換中と判定できる欄では非表示を維持します。変換状態を取得できない欄では、標準設定で入力停止からの待機時間を使って表示します。

## 起動・操作

Windows 11 x64向け。`dist/caret-mode.exe` を起動すると通知領域にアイコンが表示されます。表示ウィンドウはフォーカスを奪わず、クリックを透過します。

配布版はCランタイムを静的リンクする構成です。.NETやRustのランタイム導入は不要です。

EXEと通知領域は、黒地に白い「A」「あ」と四角枠の専用アイコンを使用します。アイコンはEXEに埋め込まれており、画像ファイルの同梱は不要です。

Chrome／エクスプローラーの一部入力欄で表示を確認しています。検証済みの範囲は `VALIDATION.md` を参照してください。

トレイアイコンをクリックすると、一時停止／再開、待機時間（300／700／1200ms）、終了を選べます。待機時間の変更は現在の実行中だけ有効です。

メニュー表示中はラベルを隠します。設定変更・再開・メニュー取消の後は、入力欄を再取得して表示を復帰します。一時停止中は非表示のままです。

半角英数字は「A」、全角英数字は「全A」です。「全A」の表示幅は36 DIP、その他は26 DIPです。

PowerShellで待機時間を指定する場合：

```powershell
& .\dist\caret-mode.exe --idle-ms 1000
```

許容範囲は100～5000ms。既に起動している場合は二重起動しません。終了する場合：

```powershell
& .\dist\caret-mode.exe --quit
```

## 対応範囲・制約

- Windowsの標準キャレット、UI Automationのキャレット範囲、MSAAのキャレットオブジェクトを利用します。
- 正確な矩形が得られない場合はUIAの隣接文字の端、それも取得できない編集欄では欄の左上付近を表示位置として使います。エクスプローラーのアドレス・検索欄では、この近似位置を使う場合があります。文字を入力してキャレットが移動しても、近似位置は正確に追従するとは限りません。
- 日本語Microsoft IMEの互換APIと英語キーボードレイアウトを初期対象にしています。その他の言語・IMEは未検証です。
- 日本語IME状態の照会は既定IMEウィンドウへのメッセージを使用する試作方式です。IME・アプリによる互換性の差があり、すべての入力欄で正しい状態を返す保証はありません。
- Chrome上部のURL・検索欄では「A」「あ」の取得とWin32上の表示状態を確認しました。Chromeのページ内入力欄、Slackデスクトップ、Chrome上のSlackは引き続き検証対象です。全入力欄・全モードへの対応は確認していません。
- ChatGPTのプロンプト欄では、「A」からひらがなモードに切り替えるだけで、文字入力前に「あ」が表示されることをユーザーが確認しました。エクスプローラーの上部アドレス・検索欄も表示確認済みです。
- ChromeのYouTube上部検索欄では、修正版で検索候補にマウスを移動しても表示が維持されることをユーザーが確認しました。その他のページ内入力欄への対応は未検証です。
- 変換状態を取得できない欄でも、位置とモードが取得できれば、操作停止から700ms後に表示します。その欄では未確定文字があっても休止中に表示される場合があります。取得できないモードを「A」に置き換えることはしません。
- 一部の欄でUIAの古い変換範囲が残るため、標準設定ではEnter／Escによる終了操作、または同じ欄で取得済みの非変換状態を補助情報として使います。新しい編集・変換通知、入力欄の切り替えで補助情報を破棄します。確実な変換終了の検出ではなく、Enterで変換段階が進むIMEや遅れた通知では、未確定文字が残っていても表示される場合があります。厳密な設定ではこの補正を使いません。
- この互換表示を使わない場合は、トレイの「変換状態を取得できない欄では非表示」をオンにするか、起動時に `--strict-composition` を指定します。その設定では、Chromeなどの欄で「あ」が表示されない場合があります。設定は実行中だけ有効です。
- パスワード欄・読み取り専用欄・非入力コントロールは、UI Automationで識別できる場合に表示しません。Document／Custom型は編集可能属性も確認します。
- Web検索欄の候補項目へアクセシビリティ上のフォーカスが移る場合、直前の検索欄と候補リストの親子関係またはControllerFor関係を確認します。検索欄内のキャレットも再取得できる場合に限り、その入力欄を表示基準にします。関連する入力欄を確定できない候補リストは非表示です。
- 候補項目に論理フォーカスがある間、入力欄自身のキーボードフォーカスを確認できない場合はIME変換状態を取得不能として扱います。標準設定では待機後の互換表示、厳密な設定では非表示になります。
- 管理者権限のアプリ、セキュアデスクトップ、リモート先、独自描画エディターは未対応または未検証です。
- Caps Lockとローマ字／かな入力方式は表示しません。「A」は半角英数字のモード表示で、大文字入力の意味ではありません。
- 自動起動登録、設定の永続化、色・サイズ変更、アプリ除外設定は今後の対象です。

入力内容・キー履歴・変換文字列を保存しません。UI Automation通知の文字列ペイロードも参照しません。入力フックは操作通知を受け取るために使用し、キー入力を遮断・書き換えません。

## 表示されない場合の診断

対象の入力欄にフォーカスを置いた状態で、以下を実行すると、座標、取得方法、モード、変換状態、非表示理由をファイルへ出力します。入力本文やウィンドウタイトルは含みません。別ウィンドウへの移動でフォーカスが変わるため、診断は遅延付きで実行してください。

```powershell
Start-Sleep -Seconds 5
& .\dist\caret-mode.exe --diagnose .\diagnostic.txt
```

5秒以内に調べたい入力欄をクリックします。`composition-unavailable` は変換中判定が取得できない状態、`caret-unavailable` は正確なキャレット位置を取得できない状態です。

継続して表示状態を調べる場合は、既存の常駐アプリを終了し、以下で起動します。

```powershell
& .\dist\caret-mode.exe --quit
Start-Sleep -Milliseconds 500
& .\dist\caret-mode.exe --trace .\runtime-trace.txt
```

ログは照会結果、状態の世代番号、待機時間、表示状態、最後の通知種別、コントロール型の番号を記録し、256KiBで記録を停止します。実際のキーコードや入力本文は記録しません。通常起動ではログを書きません。

## 開発・検証

Rust/Cargoと、MSVC C++ビルドツール・Windows SDKが必要です。

アイコンの元画像は `assets/caret-mode-icon.png`、埋め込み用は `assets/caret-mode-icon.ico` です。元画像を変更した場合は `powershell -File scripts/prepare-icon.ps1` で16～256pxの9サイズを再生成してからビルドします。

```powershell
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo build --release
```

依存バージョンは `Cargo.lock` に固定しています。依存関係がローカルにある場合は各Cargoコマンドに `--offline` を付けて実行できます。

単体テストは、IMEフラグ変換、700msの境界、連続入力、変換中の長い休止、取得不能、古い結果の破棄、DPI・画面端の配置を確認します。

日本語配列の半角／全角・ひらがな等のモードキーとAlt＋バッククォートは、通常の文字入力と区別して再照会します。日本語配列以外のOEMキーと、Altを押さないバッククォートは通常入力として扱います。[Microsoftの日本語IME操作説明](https://learn.microsoft.com/en-us/globalization/input/japanese-ime)

実際のWindowsウィンドウを使う追加テスト：

```powershell
cargo test --lib -- --include-ignored
& .\target\x86_64-pc-windows-msvc\debug\caret-mode.exe --smoke-test .\target\smoke-report.txt
```

追加テストには対話可能なWindowsデスクトップが必要です。オーバーレイの日本語描画、非アクティブ化、クリック透過、トレイ・フック登録、結果受信と終了を確認します。スモークテストは約1.2秒で自動終了します。サンドボックスでは入力フックがアクセス拒否になる場合があります。

軽量化はイベント通知と単発タイマーを中心に実装しています。入力中は高頻度の座標取得を止め、待機表示中は250ms間隔でIME状態を補助確認します。変換中と判定されたまま操作が止まった場合は500ms間隔で再確認し、確定・取消通知が欠けても復帰できるようにします。UI Automationは専用MTAスレッドで実行し、同時取得要求は1件に制限しています。フォーカス変更などの直後に取得できない場合は、250ms間隔で最大6回だけ再試行します。入力欄への切り替え途中で読み取り専用・非入力要素を取得した場合も、この短い再試行の対象です。その間は表示を隠し、編集可能な入力欄を取得できた場合に復帰します。

詳細設計は `IMPLEMENTATION_PLAN.md`、実施した検証と互換性状況は `VALIDATION.md` を参照してください。

手動でブラウザーの入力動作を確認する場合は `tests/fixtures/input.html` を開いてください。単一行・複数行・contenteditableを用意しています。

配布用フォルダーを再作成する場合：

```powershell
& .\scripts\package.ps1 -Offline
```
